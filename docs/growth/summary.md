# チャンネルを伸ばすための方針（コンサルチームのまとめ）

Ver.1.0　作成日：2026-10-23　作成：AI（朗読Part2）
もとの報告：consult-01-growth.md（成長戦略）、consult-02-data.md（データ分析）、consult-03-audience.md（視聴者と配信先）、consult-04-ops.md（制作体制）。数値と出典は各報告にある。

## 1　結論

1. いまの制約は本人の録音の時間で、AI 側の制作量ではない。台本は12回分あり、録音は1本。雨ニモマケズでは、読み直しを含めた録音時間が完成尺の約3倍だった（narration/trial-01/log.md）。伸ばす施策は、“1回の録音から作れるものを増やす” ことを軸にする
2. 新しい小さなチャンネルが短い単品だけで伸びる見込みは、前回の分析より小さい。投稿3年以内の小さなチャンネルの動画は再生の中央値が133回で、1,000回を超えたのは17％だった（consult-02 の要点2）。前回の「小さなチャンネルでも見られている」は古い動画に支えられていた可能性が高い
3. 伸びている側にあったのは、2時間以上の全編、一つの作品を通して出す連続もの、作品名より細かい単位（「夢十夜 第一夜」「枕草子 すさまじきもの」）で探す人に合わせた動画、季節の需要に合わせた公開だった（consult-01、02）
4. クリエイターチームは今は組まない。エージェントチームも使わない。サブエージェントは “読みの確認” と “公開前の確認” の2つの確認役と、月1回の調査に限って使う（4章）

## 3　注意点

- 収益化の規定では、自分で作っていない資料を「読み上げただけ」の動画が “再利用されたコンテンツ” の例に挙がっている。パブリックドメインの朗読が当たるかは確認できない（consult-01、03）。収益化に進むときに備え、読みの注記や短い語りなど本人の仕事が見える部分を入れておく
- 童話や子ども向けの詩を「子ども向け」に設定するかは本人の判断が要る。設定するとコメントや通知などが使えなくなる（consult-01）
- 2027年2月1日から、新しく申し込むチャンネルの収益化の条件が12か月で8,000時間に上がる（consult-01。YouTube 公式ブログ 2026-08-10）。最初は収益を求めない方針なので、今すぐの影響はない
- チャンネル名の仮案「声でよむ」は、YouTube 上に近い名前（「声でよむ名作本」「声で読む日本文学」など）がある。同じく仮案の「よむ夜」は、同名のチャンネルが既にある（consult-03）。朗読者名を出さないと決めたので、チャンネル名だけで見分けられる名前が要る
- 朗読者名について：データでは、肩書き（アナウンサー、声優）や朗読者名をタイトルに出した動画の数字がよかった（consult-02、前回の分析）。ただし相関で、名前で選ばれる人の動画が含まれている。本人の決定（出さない）に従い、名前の代わりに「教科書の学年」「暗唱用」「読みの注記」で見分けてもらう

## 4　クリエイターチームとエージェント編成の判断

### 4-1　クリエイターチーム：今は組まない（条件がそろえば組む）

- 制約は本人の録音で、AI の役割を分けても公開の本数は増えない。台本は在庫が十分にある
- 役割を分けると、受け渡しのたびに決まり（タイトルの書式、サムネイルの型、語りの文体）がずれる。実際に、分析で決めたタイトルの書式が trial-01 と trial-12 にしか入っていない
- 録音編集は今日、道具（tools/auto_edit.py）で自動にできた。整音と動画化も道具で回る。AI を増やす工程が残っていない
- 例外として、“確認” だけは書き手から切り離す。読みの確認役と公開前の確認役を、サブエージェントの定義として .claude/agents/ に置いた（reading-checker.md、prepublish-checker.md）
- 組む条件：本人の録音が週2本以上で4週続き、AI 側の処理が追いつかなくなったとき。または、1回の録音から作るもの（単品、ショート、まとめ版、音声版）が増えて、1つのセッションでは見きれなくなったとき
- 人間の協力者：今は無償の試聴者1人だけを勧める。AI は音を聞いて自然さを判断できない。今日の録音でも、台本と読みが違う5か所は文字起こしで見つけたが、音として自然かどうかは確かめられなかった

### 4-2　サブエージェントとエージェントチーム：サブエージェントは確認と調査に限る。エージェントチームは使わない

| 使う | 形 | 理由 |
|------|----|------|
| 作品ごとの読みの確認 | サブエージェント（reading-checker） | 作品ごとに独立し、結果が短い一覧で戻る。書いた文脈から離れて見られる |
| 公開前の確認 | サブエージェント（prepublish-checker） | 書式の取り残しや “AI 臭い” 言い回しを、別の目で1項目ずつ確かめる |
| 月1回の調査、方針の検討 | サブエージェント（今回のコンサルチームの形） | 出力が長く、主の文脈を圧迫する。結果はファイルに残る |
| 在庫の一斉の手直し（12回分の publish.md など） | 必要なときだけワークフロー | 同じ作業を多くの品目に行う。使う前に本人に規模を伝える |

使わないもの
- エージェントチーム：公式の説明では試験段階で、単一のセッションより大幅に多くのトークンを使い、順番に進む作業や同じファイルの編集には向かない（consult-04 の4-1）。この事業は、毎回作り直されるセッションが CLAUDE.md と handoff.md で引き継ぐ形で、チームの一員はセッションの再開で戻らない
- 整音・切り詰め・動画化・サムネイル：決まった処理なので、AI ではなくスクリプトで行う
- ブランドの一貫性に関わる文面と、本人とのやりとり：主セッション1つで行う

## 5　本人に決めてもらうこと（任意。答えがなくても上の施策は進められる）

- 週に何分なら録音できるか（施策の本数を決める）
- チャンネル名（「声でよむ」は近い名前がある）
- 童話や子ども向けの詩を「子ども向け」に設定するか
- 試聴者を1人頼めるか
