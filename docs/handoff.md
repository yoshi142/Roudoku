作品の選び方

- 古典の冒頭は差が大きい：枕草子（約11,000）と平家物語（約14,000、本数少）が強く、徒然草・方丈記（約1,500）は中位、おくのほそ道（約500）は短い動画では弱い。登録者245人のチャンネルの2分の枕草子が2.7万回
- 2025〜2026年に急に伸びたのは、知名度のある出演者（VTuber など）と、結末や意味を解説する動画。ふつうの朗読で最近大きく伸びた小さなチャンネルは見当たらなかった

長さ
- 5〜15分を1とすると、1〜2時間は約2.2倍、2時間以上は約2.8倍（登録者10万人未満）。5分未満は差がない。1日あたり再生も、長いほど多い

タイトル

サムネイル

- スマートフォンの関連動画欄（幅168ピクセル）で題名が読めるかを必ず確かめる

コメント（上位コメントの分類）
- 作品の感想28%、感謝21%、声・読み方への評価20%、教科書・学校の記憶15%（いいねでは23%）。読みの正確さ（難読語を滑らかに読む）が評価される。目や体が不自由で本が読めない人、日本語を学ぶ人、独居の高齢者からの感謝がある
- 「大人になって改めて聞くと感じ方が違う」という反応がある。冒頭の語りで触れる

## 7　作業環境の知見

- 作業環境は毎回作り直される。tools/fonts/ は Git に入れていないので tools/fetch_fonts.sh を実行する。Google Fonts の直接取得と GitHub の raw ファイルの取得は通らない（フォントは cdn.jsdelivr.net/gh/google/fonts から取れる）
- 作業フォルダ（scratchpad や /tmp）は消える。重要な成果は必ずリポジトリへ。大きな中間ファイル（検索結果、サムネイル画像、コメント）は入れず、集計と手順を入れる（docs/research/data/、tools/analysis/）
- YouTube：yt-dlp の動画ページ取得は 429 と「bot ではないことを確認」で止まりやすい。検索一覧（--flat-playlist）は通る。投稿日・登録者数・コメントは tools/yt_innertube.py（内部 API）で取れる。チャンネルの登録者数は channel ページの browse で取れる（1件1.5MBで重い）。サムネイル画像（i.ytimg.com）は取れる
- ウィキペディアの閲覧数（REST API）は、続けて呼ぶと弾かれる。5〜10秒空ける。ウィキソースの raw（index.php?action=raw）は User-Agent を付けると取れる。ウィキブックスの raw は連続で弾かれたので、WebFetch で取った
- メトロポリタン美術館の検索は /public/collection/v1.1/search（旧 /v1/search は 2026-10-01 に廃止）。シカゴ美術館の API はこの環境から 403。Wikimedia Commons の API は回数制限が厳しい
- OpenCV 5 には顔検出（CascadeClassifier）がない
- sleep で待つ命令は拒否される。待つときは、until のループをバックグラウンドで走らせる
- Stop フックは、未コミット・未追跡のファイルがあるとコミットとプッシュを求める。長い処理の途中で終えるときは、先にコミットする。バックグラウンドの作業が書いているファイルは、完成してからコミットする
- サブエージェントに調べ物を任せると、出典の確認に時間がかかる（教科書の調査は約36分）。結果は本人に渡す前に、重要な数値だけでも自分で原ページで再確認する（ボイジャーの日時、EU の適用日は確認済み）
- 回数制限のかかる取得は、バックグラウンドで間隔を空けて走らせ、その間に別の作業を進める

## 8　既知の問題と未検証

- 整音、切り詰め、文字起こしは、2026-10-23 に本人の録音（Pixel のレコーダー）で確かめた。手持ちの別の機材で録った場合は、ノイズ軽減の強さを無音部分の音量で決め直す（docs/knowhow.md）
- 全回の台本の「はじめに」「おわりに」は AI が書いた短い紹介。「／」（間）は読点・句点の位置に機械的に入れたので、本人が詰めてよい
- 宇宙（trial-03）と AI（trial-04）の台本は、一次情報で確認したが、本人が内容を読んで確かめてから録音するのが望ましい。ボイジャーは 2026-11-18 の1光日到達の前に公開する（以降は説明文を差し替える文案が publish.md にある）。AI の回は、EU の AI 法第50条の既存システムの印の対応期限（2026-12-02）などを扱っており、公開が遅れると古くなる
- 教科書の掲載の確認（docs/research/data/textbook_works.csv）は、確度「低」「中」の作品がある。雨ニモマケズは現行の教科書で確認できなかった。竹（萩原朔太郎）は同じ題の詩が複数あり、「光る地面に竹が生え」のほうかは未確認。文学国語は2027年度から新しい版に替わる
- 青空文庫の図書カードの罠：三好達治「雪」と萩原朔太郎「竹」は、教科書の詩が別の図書カードの詩集の中にある（narration/catalog.md の「使えなかった・注意が必要なもの」）。金子みすゞは青空文庫に収録がない。翻訳ものは訳者の権利が残る
- 方丈記の底本（國文大觀）には「こぞ破れ（やけイ）て」の異文注記がある。台本は「焼けて」で読む
- tools/analysis/ のスクリプトは、作業フォルダを基準に動く前提。作品を増やす場合は works.tsv と wiki_pageviews.py の候補を直す
- 作業の途中で見つけた誤りを直した例（同じ失敗をしないために）：サムネイル v2 の1回目は暗すぎた（暗い部分49%、基準は2割）。.gitignore が out/ 全体を除外していて、サムネイルが記録に残らなかった（v2 だけ記録に残すよう直した）。分析の1回目は、登録者数を公開しないチャンネルを 0 人として扱って結果がずれた

## 9　作業のしかた（引き継いだ AI への注意）

- 本人の文体の希望：落ち着いた平易な日本語。お世辞や評価語、誇張、流行語、最上級や確定の表現（最新版、最適、最強、確定版など）を使わない。強調は “〇〇”、引用は「〇〇」、太字（**）は使わない。出典は本文に［1］、末尾に「参考文献」（文献名と URL）。版は Ver.1.0 のように書く
- 同意より事実と正確さを優先する。前提や論理に誤りがあれば根拠を添えて指摘する。不確かなことは「分からない」と書く
- 確認は「任意の確認（答えなくても進められます）」の形でのみ行い、回答を必須にしない。依頼が遠回りなときだけ、改良した依頼文を短く示す
- 本人にしか決められないこと以外は、止まらずに作る。完了報告は、結果、変えたこと、任意の確認、の順で短く
- 作業の区切りごとにコミットとプッシュ。コミットの末尾に、その時点のセッションの指定の署名行を付ける
