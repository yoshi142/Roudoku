# 録音編集・動画編集のノウハウ

Ver.1.0　作成日：2026-10-23　作成：AI
本人の指示（2026-10-23）：録音編集と動画編集で得たノウハウは蓄積する。録音を1本処理するたびに、新しく分かったことをこの文書に書き足す（日付と、どの回で分かったかを添える）。手順そのものは tools/README.md、各回の数値は narration/trial-*/log.md に書く。

## 1　本人の録り方（決まり）

- 録音はスマートフォン（Pixel のレコーダー）。ファイルは m4a（HE-AAC 48kbps、ステレオだが左右は同じ音）で届く（2026-10-23、trial-01）
- 言い直しの合図は “同じ行を頭から読み直すこと”。手拍子はしない（本人の指示、2026-10-23）。気に入るまで何度読み直してもよい。編集では、同じ箇所を読んだもののうち最後の読みを残す
- 冒頭の挨拶と紹介は読まない（本人の判断、2026-10-23。理由：視聴者は知らない人の冒頭の語りを聞きたいと思わない）。台本の冒頭は題名と作者名だけにし、すぐ本文に入る。さらに 2026-10-23、題名と作者名も読まないことになった（本人の指示。動画は本文から始める）。題名と作者は画面の左上・説明文で示す。本人が読んでしまっても、auto_edit.py が既定で外す（--keep_head で残せる）成長戦略の報告も、冒頭10秒以内に本文を始めるよう勧めている。作品や作者の紹介は説明文と画面の文字に回す
- おわりの語りも読まない（本人の指示、2026-10-23）。本文を読み終えたら3秒黙って録音を止める
- 古典の現代語訳は読まない。字幕で原文と現代語訳を並べて出す（本人の指示、2026-10-23）。読むのは原文と、暗唱用にもう一度読む原文だけ
- 台本に句読点がない箇所（詩の行末など）でも、本人の読みには「、」と「。」にあたる間がある。編集ではこれを録音から見分ける

## 2　切り詰めと間（tools/auto_edit.py）

手順：`python3 tools/auto_edit.py <原音.wav> --out <回>/out/auto --script <回>/script.md` → report.md と phrases.tsv を読んで確かめる → `tools/process_audio.sh` で整音。

分かったこと（すべて 2026-10-23、trial-01 雨ニモマケズで確認）
- 読み直しの回数は多い。雨ニモマケズでは「欲はなく／決して瞋らず」を13回、「一日に玄米四合と」を12回、「西に疲れた母あれば」を4回読んでいた。5分56秒の録音のうち約4分が読み直しだった（録音時間 ÷ 完成尺 = 約3）
- 句の区切りは “声の音量” で取る。10ms ごとの音量で、閾値は「上位5%の音量 − 25 dB」（この録音では -44.5 dB）、0.25秒未満の途切れは句の中とみなす
- 文字起こし（faster-whisper）の単語の時刻は 0.2〜0.5秒ずれる。単語の終わりは後ろの無音に食い込みやすい。単語は “始まりの時刻” で句に割り当て、始まりが無音の中なら次の句に入れる
- 句ごとに切り出して文字起こしする方式は、文脈がなくなり聞き違いが増えた（「イカラス」「チキン」など）。使わない
- 読み直しの判定は、台本の “仮名の読み” との照合で行う。録音の時間順に並べたとき台本の位置が前へ戻らない句の組み合わせのうち、台本を最も多く覆うものを選ぶ（動的計画法）。同じ箇所の読みが複数あれば後の読みを選ぶ
  - 1句ずつ決めていく方式は、短い句（「行」「西に」）の誤判定が後ろに連鎖したので使わない
  - 一致率は 0.75 以上を同じ扱いにする。文字起こしの漢字の当て方（「四合」を「4号」と書くなど）で一致率が変わり、古い読みが選ばれたことがあった
  - 短い句（仮名3字以下）は、同じ長さ以上・一致率0.8以上でしか台本に当てない。1字だけで別の箇所に当たりやすい
  - 残した句と句のあいだの「残さなかった句」の並びに読み直しが1つでもあれば、並び全体を読み直しとみなす。台本に当たらない断片（文字起こしの「分か」など）を拾わないため
  - 台本にない語でも、読み直しと無関係なら残して「要確認」の印を付ける（本人の読みを黙って削らない）
  - 題名と作者名は、台本の見出し「# 台本：作者「題名」」から読み取り、台本の先頭に足して照合する。題名と本文1行目が同じ（雨ニモマケズ）でも題名を捨てずにすむ
- 仮名の読みは fugashi（unidic-lite）で出す。pykakasi は「陰」を「いん」、「一日」を「ついたち」と読み、照合を誤らせた。fugashi も「行って」を「おこなって」、「分か」を「ぶんか」と読むことがある。数字は先に漢数字に直す
  - 入れ方：`pip install --use-pep517 fugashi unidic-lite`（この環境では --use-pep517 がないとビルドに失敗した）
  - pykakasi に改行を含む文字列を渡すと文字が重なる。空白と改行を除いてから渡す
- 「、」と「。」の見分け：句の後ろの間（本人が次に声を出すまで）が 1.0秒以上なら「。」、それより短ければ「、」。録音ごとに大津の方法で2群に分けて境を決める（1.0〜3.0秒に収める）。雨ニモマケズでは行の途中の間が 0.3〜0.9秒、行末が 1.0〜3.9秒で、自然に分かれた
- そろえる長さ：「、」0.6秒、「。」1.5秒、題名と作者名のあと 2.0秒、冒頭 1.5秒（動画は黒から1.2秒でフェードインするので、画面が出てから本文が始まるように。2026-10-23 に 0.6秒から変更）、末尾 2.5秒。句の前に 0.06秒、後ろに 0.18秒の余白を付け、両端に 12ms のフェード
- 台本との違いは、残した読みを仮名にして台本と比べ、report.md に表で出す。仮名変換の誤りも混じるので、目で確かめてから本人に伝える
- 文字起こしの精度：small より medium、medium より large-v3 が安定する。台本の本文を initial_prompt に渡すと固有名詞と漢字が安定する。large-v3 でも台本どおりに直されることはなく、本人の読み違いはそのまま出た（「わらの束」「ああいうものに」）。medium で約2分の音声に1分前後、6分の録音に3〜4分（CPU）

### 録り直しの差し替え（2026-10-23、trial-01 の2本目の録音で確認）
- 録り直しは、元の録音のあとに並べて `auto_edit.py 1本目.wav 2本目.wav ...` に渡す。3秒の無音をはさんでつなぎ、台本との照合で同じ箇所はあとの読みが選ばれる。手作業の差し替えはいらない
- 本人はカードの範囲より広く（「一日に」から終わりまで）読み直していた。範囲が広くても問題ない
- 2本目は1本目より 1.4 dB 小さかった。つなぐ前に2本目以降の音量を1本目にそろえる（自動）
- 「。」の境は録音ごとに違った（1本目 1.0秒、2本目 1.8秒）。ファイルごとに決める（自動）
- 文字起こしは、録音の冒頭や無音に「ご視聴ありがとうございました」を作ることがある。また実際にはない数字（「222ほめられもせず」）を作ることがある。どちらも除く（clean_words）
- 動的計画法で “あとの読み” を優先する重みは、句の数ではなく字数に比例させる。句の数で足すと、細切れの断片（「み」「そと」）を多く拾う組み合わせが得をして、古い読みの断片が選ばれた。1字の句は照合に使わない
- 録り直した結果の照合：台本と違う読みは0になった（残った差は仮名変換の誤り：「行って」を「おこなって」と読むなど）。「ひどり」は文字起こしでは「左」と書かれた

## 3　整音（tools/process_audio.sh）

- スマートフォンの録音は、子音の瞬間的なピークが平均より 20 dB 以上高い。loudnorm の線形モードでは -14 LUFS に届かず、動的モードに切り替わって音量が揺れた（2026-10-23、trial-01）
- 対策：軽い圧縮（-26 dB から 2.5:1）→ 目標まで音量を上げる → リミッター（-3 dBFS）。目標は -16 LUFS。-14 にするとピークを約10 dB 削ることになり、声がつぶれるおそれがある。YouTube は大きい音を下げるだけなので、-14 の動画より約2 dB 小さく聞こえる。-16 はポッドキャストで一般的な値で、音声配信にもそのまま使える
- 結果（trial-01）：-16.5 LUFS、トゥルーピーク -1.1 dBTP、LRA 4〜5 LU
- Pixel のレコーダーは録音時にノイズ抑制がかかっていて、無音部分はほぼデジタル無音。ノイズ軽減（afftdn）は弱く（4 dB）。手持ちの別の機材で録った場合は、無音部分の音量を見て強さを決める
- 原音は narration/trial-*/raw/ に無加工で保存する（m4a の元ファイルと、WAV に直したもの）。Git には入れない

## 4　動画とサムネイル

- 動画は静止画1枚と音声（tools/make_video.sh、1920×1080、30fps、H.264/AAC）。2分の動画の書き出しに約1分
- 朗読者名は出さない（本人の決定、2026-10-23）。サムネイルと動画の静止画は、題名・作者名（・作品名）だけにする。make_thumbnail_v2.py の --narrator は使わない
- 既存のサムネイルを作り直すときに設定値が分からなければ、候補の設定で作って元の画像との画素の差が最も小さいものを選ぶと再現できた（trial-01、02、05）。作り直したときは、使った設定値を docs/thumbnail/README.md に書く
- チャプターは、0:00 から始まり10秒以上の区切りが3つ以上あるときに表示される。2分前後の詩には付けない

- 字幕（tools/make_subtitles.py、2026-10-23）：文字は台本から取る（文字起こしではない）。auto_edit.py の timeline.json にある「句が完成音声の何秒か」と「台本の位置」で、台本の行ごとに表示時刻を決める。台本の仮名の位置は行ごとに仮名にしてつないだもので数える（全体を一度に仮名にすると、行の境で位置がずれた）。台本に当たらない短い句は時間の近いほうの行に入れる
- 字幕の見た目：しっぽり明朝 Medium 68px、生成りの白を少し透かし、細い暗い縁をぼかす（\blur2.5）。画面中央。フェードは入り 0.6秒・出 0.5秒。読み始めの 0.25秒前に出し、読み終わって 0.7秒（次の行の手前まで）残す。YouTube に上げる用の SRT も同時に作る
- 動画の背景（tools/make_video_bg.py）：サムネイルは中央に大きな題名があり字幕と重なるので、動画には別の背景を使う。版画を 42% の明るさにし、1.6px ぼかし、中央に柔らかい楕円の下地。題名と作者名は左上に小さく。版画の紙の余白が出ないよう zoom 1.15 前後で切り抜く。左上に版画の題字がある場合は、そこだけ柔らかく暗くする
- 音楽（tools/make_reading_video.py）：声より 20 LU 小さく（WCAG 1.4.7 の「20 dB 以上」に合わせる）、声が出ているあいだはさらに約 4 dB 下げる（sidechaincompress）。冒頭 3秒・終わり 5秒でフェード。曲の権利は tools/music/README.md。暗唱用の回は音楽を入れない（学習の妨げになる研究がある。docs/growth/brand-summary.md）
- ffmpeg で静止画を -loop 1 で読むときは、必ず -t（長さ）を付ける。付けないと終わらない（試験の書き出しで一度止まらなくなった）
- 2分の動画（字幕と音楽つき、30fps）の書き出しに約1分50秒
- 背景の音は物語に合わせて選ぶ（本人の指示、2026-10-23）。雨ニモマケズは雨の音（CC0 の夕立の録音）にした。環境音は make_reading_video.py の --ambient で重ね、声より 20 LU 小さく、声のあいだは 2 dB だけ下げる（音楽の 4 dB より小さく。環境音が読みに合わせて上下すると不自然）。録音の冒頭に無音がある素材は --ambient_start で飛ばす。使う前に 10秒ごとの短期ラウドネスを見て、雷などの急な大きな音がないか確かめる。作品と音の対応は tools/music/README.md の「作品ごとの選び方」
